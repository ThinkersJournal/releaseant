# ReleaseAnt roadmap

Order matters: survey, then design, then code. Every code row ships with a negative control (a test that fails when the behaviour is removed).

R0. Survey: read the publish scripts this portfolio already hand-wrote (tools/pub-one.cmd and /tmp/claim-retry.sh in the PM's tree, scripts/publish.ps1 in baracuda, the fuel and auth-framework publish loops described in PORTFOLIO-ROADMAP) and list every behaviour they share. Deliver docs/SURVEY.md.
R1. Design: docs/DESIGN.md with the publish-set computation, the ledger format, resume semantics, rate-limit policy, read-back, yank policy, and a test plan with a negative control per trap above.
R2. Core library crate `releaseant` (graph, plan, ledger) with tests against a fake registry.
R3. CLI `releaseant plan|verify|publish|resume|readback` (dry-run default).
R4. Real-registry rehearsal against a throwaway set of placeholder crates, then first real use on dirty-ranges.
R5. Adopt in fuel (43 crates) and baracuda (10-crate set); retire the hand-written loops.
R6. Pre-upload metadata check (PM, 2026-10-29: a multi-crate publish that dies at crate 7 of 13 leaves a half-published set, the thing this tool exists to prevent). Done in 0.0.16, split by who refuses (PM, 2026-10-29): ERRORS stop `plan`, `verify` and `publish` before anything is written, every problem of every crate listed: no `description`, neither `license` nor `license-file`, more than 5 `keywords` or one crates.io refuses (ASCII, at most 20 characters, starting alphanumeric, only letters, digits, `_`, `-`, `+`), more than 5 categories or one that is not a crates.io slug, a named readme or licence file that is missing. WARNINGS (listed on stderr, exit 0): no `repository`, README, `keywords`, `categories` or `rust-version`, because the registry accepts the crate without and every real set publishes without some of them today (docs/ADOPTION.md open item 1). `--require-metadata FIELD,...` turns chosen warnings into errors (the recommendation for single-crate Ants we ship now: `keywords,rust-version,readme`) (`src/preflight.rs`, `src/categories.rs`). Done in 0.0.18: the setting for the required fields, a `releaseant.toml` at the repository root read from the commit being published (`[metadata]`, `require = [...]`; unknown keys and field names are errors; the flag adds to it; `src/config.rs`). Done in 0.0.24: `homepage` and `documentation` can be named in `--require-metadata` or `releaseant.toml` (never warned about by default, because crates.io links docs.rs and the repository without them). Owed before any releaseant release (PM, 2026-10-30): the patent re-sweep for the partial-publish and tagging capability family (`--only`, `plan --registry`, per-crate tags; `docs/PATENT-SWEEP.md`), then record it there. 0.0.32 recorded a seventh pass (3 queries, 3 claim-1 reads, low confidence, sweep INCOMPLETE); the owed re-sweep is NOT done. Later: refresh `src/categories.rs` from crates.io; a pre-upload check that cargo's `rust-version` is not older than the dependencies need. Done in 0.0.25: the WIPO Patentscope pass over ideas 1 to 9 (route B in `docs/PATENT-SWEEP.md`, sixth pass: found nothing, low confidence); the other unrun routes are not scheduled. Candidates from the real publishes (`docs/FIRST-REAL-USE.md`; first-hand, PM, 2026-10-30): a progress line per crate with elapsed time (done in 0.0.27); `--only <crate>` and a plan that marks registry state (done in 0.0.29); a tag name per release or tagging only a fully published plan (done in 0.0.31: `--only --tag` tags each selected crate `<crate>-v<version>`; the project `v<version>` only for a run that publishes the entire plan). Second-hand: refuse a target version the registry already holds; check the commit is still `origin/main`'s tip.
